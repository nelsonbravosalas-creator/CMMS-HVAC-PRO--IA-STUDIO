Mapa Estructural (Interactivo)

Comparativa de Flujos y Reglas de Negocio

Flujo Actual (Con Asimetrías)

  • Múltiples endpoints (`/api/sync`, `/api/sync/informes`) sin un pipeline central unificado.
  • Sincronización manual dispersa en UI (ej: `EditorInforme` llamando a `fetch` antes del motor Dexie).
  • Tipos de datos inconsistentes (ej: uso de arreglos de strings para técnicos vs UUIDs foráneos).
  • El motor offline (`DBLocal`) delega resolución de conflictos al backend mediante timestamps, pero la UI puede enviar datos antes de encolar.

Flujo Óptimo (Reglas de Negocio)

  • UI Offline-First: La UI interactúa *exclusivamente* con Dexie store/zustand (`saveData`).
  • SyncWorker Central: Un único proceso en background lee la `sync_queue` y realiza upserts masivos en `/api/sync`.
  • Integridad Referencial: Relaciones fuertes usan IDs (`uuid_sync`) en lugar de strings de visualización.
  • Soft Deletes Universales: Toda eliminación actualiza `deleted_at`, propagado por `sync_queue`.

Puntos de Estandarización & Upgrade

1. Refactor de Repositorios (Zustand + Dexie)

Desacoplar llamadas `fetch` de los componentes React. Todo `onClick={save}` debe inyectar mutaciones a `Zustand`, el cual actualiza `Dexie` e inserta registro en la tabla `sync_queue`. Cero red externa en Componentes.

2. Pipeline de Sync Backend (`upsert_bulk`)

Convertir endpoints segmentados a un `POST /api/sync/commands` que reciba CQRS ops (inserts, updates). El server evalúa los `updated_at` (LWW: Last Write Wins) y confirma IDs.

3. Normalización Postgres

Convertir campos repetidos en las tablas `JSONB` hacia tablas relacionales explícitas u homogeneizar `JSONB` validados en esquema. Evitar que `activos` contenga arreglos JSON crudos sin ID referencial.

Infraestructura

  • Hosting App: Google Cloud Run
  • DB Remota (Server): PostgreSQL
  • DB Local (Client): IndexedDB / Dexie.js
  • Framework: React + Vite + Express
  • Backend: Node CJS SSPA
